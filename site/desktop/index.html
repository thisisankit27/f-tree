For your laptop

f-tree on Windows and Ubuntu.

Opens a .ftree exported from the phone and draws it the way the phone does — a generation is a column, ancestors at the left. Free, open source, no account.

Beta This is an early build and it will have rough edges. It is new, it has been tested by very few people, and it may misbehave — expect that rather than a finished app. The one thing it cannot do is damage your family tree: it only ever reads the .ftree you open, and never writes to it. Building and editing a tree is still the Android app's job.

Windows Your system

Windows 10 or 11, 64-bit. Installs for your account, so it never asks for an administrator password.

Ubuntu & Linux Your system

Take the .deb on Ubuntu, Debian or Mint — it is the one that needs nothing from you afterwards. The other two ask for a command first.

Finding the latest build…

One thing to expect on Windows. The installer is not code-signed — there is no certificate behind it — so Defender will stop it with “Windows protected your PC” and the publisher will read Unknown. Choose More info, then Run anyway. Every file here is built in the open by GitHub Actions, and each has a checksum you can check on the page that follows your download.

Good to know

Which Linux file should I take?

The .deb, unless you have a reason not to. It puts f-tree in your applications menu like anything else, updates cleanly, and — the part that matters on current Ubuntu — it is the only one of the three that can set up Chromium’s sandbox helper for you.

That caveat applies to both of the other formats, so it is worth understanding once. Ubuntu 24.04 and newer stop an ordinary program from using the sandbox Chromium prefers, so it falls back to a small helper that has to be owned by root. A package installer can arrange that; an archive you unpacked yourself cannot. Start one of those builds without arranging it and the app exits on the spot, complaining about chrome-sandbox. The portable folder is still perfectly usable — it needs one sudo chmod, printed on its download page — but it is no longer the answer for a machine you do not administer, and we would rather say so than let you find out.

The AppImage is the one to avoid on those releases. It has a second, unrelated problem: they replaced the FUSE 2 helper it needs with fusermount3, so it will not start by double-clicking, and installing libfuse2 does not fix it, whatever the internet says. Running it as ./f-tree-*.AppImage --appimage-extract-and-run gets past that and walks straight into the sandbox problem above — which cannot be solved for a folder that is unpacked fresh into a temporary directory every time it runs.

Is there a macOS build?

Not yet. Windows and Linux are what is built and tested today.

What can the app reach?

It reads the file you open and writes one small note of which file that was, so it can reopen it next time. No account, no server, no telemetry. The window itself is refused the network outright — which is why its typefaces are read from disk rather than fetched from Google. The only request the app can make is the update check, and that is off until you switch it on in Updates.

How do updates work?

Two switches under Updates, both off when you install: check automatically, which looks once at startup and stays quiet unless there is something to say, and offer me betas, which asks before it turns on. Anything downloaded is checked against the SHA-256 GitHub published for it before you are offered it to run; if they disagree the file is deleted and nothing is installed.

What does it do today?

It reads a tree: the chart, the people index, the search and the relation finder. Editing, settings and Hindi kinship are being built. Building and editing a tree is the phone's job for now, and the Android app does all of it.
